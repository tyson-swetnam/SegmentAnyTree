## Project Overview

**This is a fork of [SmartForest-no/SegmentAnyTree](https://github.com/SmartForest-no/SegmentAnyTree)** focused on:
- Updating the Docker build environment for reliability and reproducibility
- Finding and implementing computation speed improvements for inference and training

SegmentAnyTree is a deep learning framework for **tree instance segmentation from 3D point cloud data** (LiDAR). It builds on the [torch-points3d](https://github.com/torch-points3d/torch-points3d) framework and implements panoptic segmentation (combined semantic + instance segmentation) using the PointGroup architecture with a 3-head variant. The primary model is `PointGroup-PAPER`.

Paper: Wielgosz et al. (2024), "SegmentAnyTree: A sensor and platform agnostic deep learning model for tree segmentation using laser scanning data", Remote Sensing of Environment.

### Fork-Specific Notes

### Backend Status
- **MinkowskiEngine (CUDA 11)**: Production-ready. Validated at 47/64 GT trees matched on FOR-instance RMIT benchmark. Use `segmentanytree:cuda11`.
- **SpConv v2.x (CUDA 12)**: Experimental. Auto-converts ME weights at load time. Semantic segmentation biased (~100% tree). Instance clusters don't match ground truth. Needs retraining with SpConv for correct results.
- Model weights (665 MB) stored via Git LFS — `git lfs pull` required before Docker builds. Dockerfiles fail-fast if weights are LFS pointers.
- Local conda env: `/opt/tswetnam/miniforge/envs/sat` (CUDA 12.4 + SpConv)

## Build & Run Commands

### Docker (primary usage)
```bash
# IMPORTANT: Pull model weights before building (requires git-lfs)
git lfs pull --include="model_file/PointGroup-PAPER.pt"
make verify-weights  # Should report ~665 MB, not 134 bytes

# Build CUDA 12.4 (recommended) or CUDA 11.8 (legacy)
make build-cuda12
make build-cuda11

# Run JupyterLab (default)
docker run --gpus all -p 8888:8888 \
  -v $HOME/data/input:/data/input \
  -v $HOME/data/output:/data/output \
  segmentanytree:cuda12

# Run batch inference
docker run --gpus all \
  -v $HOME/data/input:/data/input \
  -v $HOME/data/output:/data/output \
  segmentanytree:cuda12 \
  bash scripts/run_inference.sh /data/input /data/output true
```

## Architecture

### Package Layout
- **`sat/`** — Python package with pipeline, I/O, metrics, and preprocessing modules
  - `sat/pipeline/` — Inference pipeline steps (coordinate_transform, config_update, result_merge, etc.)
  - `sat/io/` — Point cloud file I/O (LAS, PLY, format conversion including COPC)
  - `sat/metrics/` — Instance segmentation evaluation metrics
  - `sat/preprocessing/` — Point cloud sparsification and filtering
  - `sat/compat/` — Compatibility shims replacing C++/CUDA dependencies with pure PyTorch
  - `sat/clustering/` — Pure PyTorch region_grow clustering implementation
  - `sat/utils/paths.py` — Central path resolution via `SAT_ROOT`/`SAT_DATA` env vars
- **`torch_points3d/`** — Core ML framework (PointGroup model, trainer, datasets, modules)
- **`conf/`** — Hydra configuration (model architectures, data configs, training params)
- **`scripts/`** — Shell scripts for inference, batch processing, Docker, training
- **`notebooks/`** — JupyterLab notebooks (quickstart, inference, COPC, batch, visualization)
- **`tests/`** — Automated tests (test_io, test_pipeline, test_paths, test_gpu_profile)

### Configuration System
Uses **Hydra 1.x** for hierarchical config composition. All configs live in `conf/`. Runtime eval config (`conf/eval_run.yaml`) is generated by the pipeline from the template `conf/eval.yaml`.

### Inference Pipeline (`scripts/run_inference.sh`)
1. Sanitize filenames → 2. UTM→local coords → 3. Model inference via `eval.py` → 4. Rename outputs → 5. Merge results with original point cloud → 6. Restore UTM coords → 7. Convert to COPC via PDAL

### Compatibility Shim System (`sat/compat/`)
The codebase replaces the unmaintained `torch-points-kernels` C++/CUDA package with pure PyTorch implementations. `sat/compat/install.py` injects fake modules into `sys.modules` so that existing code doing `import torch_points_kernels` resolves to our pure-PyTorch replacements (`ball_query`, `knn`, `region_grow`, `instance_iou`). This shim is installed automatically when `eval.py` or `train.py` runs.

### Sparse Backend Abstraction (`torch_points3d/modules/SparseConv3d/nn/`)
Three sparse convolution backends are supported via dynamic module swapping:
- **`__init__.py`**: Tries backends in order (spconv → torchsparse → minkowski), exports unified API (`Conv3d`, `BatchNorm`, `SparseTensor`, etc.), overridable via `SPARSE_BACKEND` env var
- **`spconv.py`**: Wrapper around SpConv v2.x with critical adaptations:
  - Coordinate reordering: SpConv uses `[batch, z, y, x]` internally; wrapper exposes `[batch, x, y, z]` to match MinkowskiEngine convention
  - 32-voxel margin added to all coordinates to prevent strided convolution validation failures at boundaries
  - Auto-generated indice keys pair encoder/decoder layers in UNet architectures
  - Skip connection filtering clips decoder output back to encoder coordinates to prevent exponential voxel growth

### Weight Migration (`scripts/migrate_weights.py`)
Pre-trained MinkowskiEngine weights require two transformations for SpConv:
1. **Key rename**: `*.kernel` → `*.conv.weight`
2. **Kernel reshape**: ME stores as `(K³, C_in, C_out)` 3D; SpConv expects `(C_out, kD, kH, kW, C_in)` 5D. For 1x1 convs: `(C_in, C_out)` → `(C_out, 1, 1, 1, C_in)`.

The checkpoint is nested: `ckpt['models']['latest']` contains 755 parameters (118 kernels + 637 BatchNorm/MLP). All model variants (latest, best_F1, etc.) are converted in one pass. Non-kernel parameters (BatchNorm, MLP heads) transfer unchanged.

Usage: `python scripts/migrate_weights.py --input model_file/PointGroup-PAPER.pt --output model_file/PointGroup-PAPER-spconv.pt`

### Model Architecture (`torch_points3d/models/panoptic/PointGroup3heads.py`)
PointGroup 3-heads variant with:
- **Backbone**: UNet sparse convolution (4 layers) via `SparseConv3d()` factory
- **Three output heads**: semantic (num_classes), offset (xyz center voting), embedding (discriminative loss)
- **Three parallel scorer networks**: ScorerUnet, ScorerEncoder, ScorerMLP — each scores cluster proposals independently
- Model instantiation is config-driven via `torch_points3d/applications/sparseconv3d.py` factory, which reads YAML from `torch_points3d/applications/conf/sparseconv3d/`

### Environment Variables
All paths are derived from environment variables (no hardcoded paths):
- `SAT_ROOT` — Project root (auto-detected from git or script location)
- `SAT_DATA` — Data directory (Docker: `/data`)
- `SAT_MODEL` — Model checkpoint directory
- `SAT_CACHE` — Temporary files
- `SPARSE_BACKEND` — Sparse convolution backend: `spconv` (default), `torchsparse`, or `minkowski`
- `SAT_GPU` — GPU device index for single-GPU inference (default: 0, set by parallel launcher)
- `NUM_GPUS` — Number of GPUs for parallel inference (default: auto-detect all)

### Key Technical Details
- **Python 3.10**, **PyTorch 2.5.1**, **CUDA 12.4** (Docker base: `nvidia/cuda:12.4.1-cudnn-devel-ubuntu22.04`)
- Sparse convolution backend: **SpConv v2.x** (`spconv-cu124`, pip-installable)
- Clustering: Pure PyTorch `region_grow` implementation (`sat/clustering/region_grow.py`) using `torch_cluster.radius()`
- Backend abstraction: `torch_points3d/modules/SparseConv3d/nn/` supports spconv, torchsparse, and minkowski backends via `SPARSE_BACKEND` env var
- GPU scaling: Auto-detects GPU memory via `sat/gpu_profile.py` to scale `cluster_nsample` (32 default → 200 on A100 80GB), `num_workers`, and `batch_size`
- Multi-GPU: parallel inference via `scripts/run_inference_parallel.sh`; COPC octant-parallel via `scripts/run_inference_copc.sh`; DDP training via `torchrun`
- Performance: Numba-accelerated union-find in `region_grow` (50-100x vs Python); joblib-parallelized result merge; CPU-aware num_workers auto-tuning
- Pre-trained model: `model_file/PointGroup-PAPER.pt` (use `scripts/migrate_weights.py` to convert from ME format)
- Input formats: .las, .laz, .ply; Output format: .copc.laz with PredSemantic + PredInstance fields
- Docker images: `harbor.cyverse.org/vice/segmentanytree:cuda12` (recommended) and `harbor.cyverse.org/vice/segmentanytree:cuda11` (legacy)
